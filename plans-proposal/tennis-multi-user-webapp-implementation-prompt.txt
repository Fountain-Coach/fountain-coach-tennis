Implementation Prompt — Convert Tennis
App to Full Multi-User Web Application
Implementation Prompt
Objective
Convert the existing feature-complete, self-contained tennis application into a production-ready
multi-user web application.
The current application is the behavioral and visual specification.
Preserve:
• the current UI template;
• the existing frontend structure;
• the existing user-facing workflows;
• the current domain terminology;
• all existing calculations and rules;
• all current entities and relationships;
• all current user-visible functionality.
The migration must add a proper shared backend, authentication, authorization, administration, and
relational persistence without unnecessarily redesigning the current frontend.
The target architecture is:
Browser
↓
Existing Tennis Frontend Template
↓
Authenticated Application API
↓
Application Service
↓
Server-side SQLite
GitHub OAuth provides identity.
The tennis application itself owns authorization, roles, administration, and application data.
